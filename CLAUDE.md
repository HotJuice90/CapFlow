## Память (Memora MCP)

В проекте настроен MCP-сервер персистентной памяти `memora` (`.mcp.json`,
локальный SQLite в `.memora/`, в `.gitignore`). Она НЕ хранит структуру кода
(это дублировало бы то, что и так видно через Read/Grep, и мгновенно
устаревало бы) — только решения/вкус/баг-классы, которых код сам не показывает.

- **В начале задачи**, если тема похожа на что-то уже решённое (конкретный
  цвет/размер/анимация/паттерн, а не «почини этот новый баг») — сначала
  `memory_digest(topic)`, а потом при необходимости грепать код. Экономит
  разведку: не гадать заново то, что уже обсуждали.
- **После нетривиального решения** (не то, что и так лежит в этом файле) —
  коротким `memory_absorb(facts=[...])`, тег `capflow`. Годится: почему выбран
  конкретный вариант анимации/паттерна, найденный класс багов, отвергнутая
  альтернатива. НЕ годится: то, что и так тут написано, факты, выводимые из
  текущего кода (пути файлов, актуальная структура — она меняется, память нет).

## Философия

Приложение для учёта инструментов с прогнозируемой доходностью. Добавляем только
инструменты с фиксированной или почти фиксированной ставкой, которую можно
посчитать заранее (вклад, накопительный счёт, облигации с фикс. купоном, ЦФА).
НЕ добавляем то, где доход рыночный/непредсказуемый наперёд: акции, ПИФы/фонды,
ETF, облигации-флоатеры, структурные продукты. ИИС — не тип инструмента, а
налоговая обёртка над теми же вкладами/облигациями.

## Разработка БЕЗ Metro (по умолчанию)

Metro регулярно отваливался и терял времени больше, чем сама сборка — поэтому
основной цикл разработки теперь **без него**: в `android/app/build.gradle` в блоке
`react { ... }` стоит `debuggableVariants = []` — debug-сборка тоже зашивает JS-бандл
на этапе компиляции (как release), приложению Metro на устройстве не нужен вообще.

Рабочий цикл на пачку правок:
1. `cd android && ./gradlew :app:assembleDebug` (~1.5 мин, без минификации — быстрее release)
2. `adb install -r app/build/outputs/apk/debug/app-debug.apk`
3. Приложение открывается сразу офлайн, без сплеша/зависаний на ожидании Metro.

Важно: `android/` в `.gitignore`, `debuggableVariants = []` — правка только локальная,
её не завезёт `git clone`/новый воркитри. Если `android/` когда-то пересоздаётся
(prebuild и т.п.) — проверить, что настройка на месте, иначе debug-сборка молча
откатится на дефолт (требует Metro) и опять будет «сплеш висит» без видимой причины.

Дев-клиент с живым Metro (fast refresh) остаётся резервным вариантом, если нужен
именно live-reload — но по умолчанию не используем.

## Шрифт

- **Onest везде** через локальные TTF в `assets/fonts/`. Грузятся в `app/_layout.tsx`.
- Глобальный дефолт: `src/theme/globalFont.ts` патчит `Text`/`TextInput` через
  `require('react-native')` и подставляет нужное семейство по `fontWeight`.
- На Android именованный шрифт игнорирует `fontWeight` — поэтому каждый вес = своё семейство:
  `Onest_400Regular` → `_500Medium` → `_600SemiBold` → `_700Bold` → `_800ExtraBold`.
- Семантические алиасы в `src/theme/tokens.ts` → `font.regular`/`medium`/`semibold`/`bold`/`extrabold`.
- **Вёрстка 1:1 по Фигме, однострочный текст**: у пользователя в Фигме интерлиньяж
  всегда 100% (без запаса), отступы он крутит только через gap/margin между
  текстовыми фреймами. В RN без явного `lineHeight` подставляется нативный
  интерлиньяж шрифта (у Onest заметно больше 100%) — из-за этого одинаковые
  цифры gap/margin визуально не совпадают с Фигмой. Правило: для каждого
  однострочного текста из Фигмы ВСЕГДА задавать `lineHeight` явно — эмпирически
  для Onest подходит `fontSize + 2` (ровно `fontSize` жмёт тесно). После этого
  брать отступы между фреймами из Фигмы как есть, без ручной подгонки.

## Канон экранов

- **Top padding контейнера экрана = 80** (без `insets.top` — статус-бар уже под маской из `_layout.tsx`).
- **Горизонтальные поля = 16** (через `tokens.spacing.screenH`). Не использовать 20 без явного запроса.
- **Заголовок экрана**: `<ScreenTitle>...</ScreenTitle>` из `src/components/ScreenTitle.tsx`
  (Onest SemiBold 34pt, letter-spacing -1% / -0.34, marginBottom 16).
- **Padding bottom** там, где экран должен заходить под плавающий таб-бар: `insets.bottom + 80`.
  Tab-bar плавающий: `bottom:16`, height `66` = 82px от низа + safe-area.
  С включёнными подписями (Настройки → «Подписи в навбаре») бар выше на 10px —
  на экранах с `+90` просвет остаётся, а конвертер (`+66`) бар слегка накрывает.
- **Внутри карточек/списков (бенто) верт. паддинг ≥ горизонтального.** Если по бокам 16 —
  сверху/снизу тоже минимум 16 (можно больше, нельзя меньше). Частый косяк: обёртка задаёт
  только `paddingHorizontal`, а верт. отступ — это `paddingVertical` первой/последней строки
  списка (обычно `tokens.spacing.md` = 12) — тогда край получается уже боков. Компенсировать
  добавлением `paddingVertical` на самой обёртке (см. `app/(tabs)/settings.tsx` → `Group`,
  `app/(tabs)/index.tsx` → `styles.listInner`).
- **Заголовок секции (не экрана — `<ScreenTitle>` отдельно)**: `fontSize: tokens.typography.title`
  (20), semibold, `marginTop: 40`, `marginBottom: 14`, `paddingLeft: 8`. Устоялось итеративно
  в аналитике (`app/(tabs)/analytics.tsx` → `styles.section`), теперь то же самое в
  `app/(tabs)/index.tsx` → `styles.sectionTitle`. При добавлении нового раздела на любом
  экране — брать эти числа, не изобретать свои. Если заголовок идёт сразу под hero-виджетом
  (донат/график) — сверху может понадобиться больше (аналитика перед «Состав портфеля» берёт
  48 вместо 40) — сверять с Figma, не копировать базовые 40 не глядя.

  Селекторы и расчёты — `src/state/selectors.ts`.
- **Тумблер**: `src/components/Toggle.tsx`, используется через `SettingsRow`'s
  `toggle={{ value, onChange, offColor? }}`. Дефолтный OFF-цвет трека
  (`tokens.surface.neutral`) рассчитан на белую карточку под ним. Если тумблер
  лежит прямо на градиентном фоне экрана (без своей белой подложки) —
  ОБЯЗАТЕЛЬНО передавать `offColor: tokens.surface.tabOff` (тот же токен, что
  у неактивных чипов в `app/catalog/instruments.tsx` → `tabChip`), иначе трек
  сливается с фоном. Пример: `app/settings/data-format.tsx`.
- **Переключатели с плашкой (табы/чипы/сегменты) — на КЛАССИЧЕСКОМ `Animated`,
  не на reanimated.** `Animated.Value` кладётся прямо в стиль: его значение
  читается при рендере и попадает в нативные пропсы ТОГО ЖЕ коммита, а
  `setValue` в `onLayout` толкает его в нативную вью сразу — плашка встаёт на
  место в том же кадре, в котором пришли замеры. `useAnimatedStyle` так не
  умеет: он считается на UI-потоке ВНЕ коммита React, апдейты shared value
  уезжают туда асинхронно, и до их приезда анимированный стиль навязывает
  `width: 0`. Подстраховать его обычным стилем НЕЛЬЗЯ — анимированный всегда
  главнее; можно только не класть в него то, что нужно с первого кадра.
  Симптом: «активный таб/иконка подгружается» — на занятом JS-потоке успеваешь
  сделать скриншот. Стоило 4 сборок и 2 неверных диагнозов (0.8.93–0.8.97),
  чинилось в `SegmentedTabs` / `SlidingChipTabs` / `TabChip`; образец подхода —
  `D:\Poznanie app\components\ui\SegmentedTabs.tsx`. Приём: стартовое состояние
  задавать в конструкторе `Animated.Value`, а первый прогон эффекта пропускать
  по `mounted`-флагу — тогда на монтировании не анимируется ничего.
- **Тот же класс шире**: любое свойство, которое нужно на ПЕРВОМ кадре, нельзя
  отдавать исключительно анимированному стилю. `opacity`/`rotate` безопасны —
  их дефолты (1 и 0) и есть стартовое состояние. `width`/`backgroundColor`/
  `color` — нет: их дефолт это «нулевой размер» и «без цвета», то есть
  невидимость. Родственная грабля: подмена одного типа компонента другим по
  условию (`focused ? IconA : IconB`) заставляет React пересоздавать поддерево —
  на SVG это давало ту же задержку в навбаре; лечится тем, что оба варианта
  смонтированы всегда и переключается `opacity`.
- **Свайп-карусель / пагинация (ЖЕСТОВАЯ анимация)**: только через
  `react-native-reanimated` + `react-native-gesture-handler`, НЕ через классический
  `Animated` API. Это правило про жест и не противоречит пункту выше про табы:
  там анимация от тапа, JS-поток свободен. Причина: `Animated` не даёт native
  driver на `width`/`backgroundColor`,
  из-за этого анимация точек/пилюли дёргается на JS-потоке при нативном fling —
  этого категорически нельзя вылечить внутри `Animated`, проверено на практике
  (см. историю мучений с пагинацией целей на главном экране). Принцип:
  - Один `SharedValue<number>` = позиция скролла в пикселях (`pos`). НЕ дискретный
    индекс — вся анимация выводится как `interpolate(pos.value, [...], [...])`
    от расстояния до "домашней" позиции каждого элемента (`index * SLIDE_WIDTH`).
  - `Gesture.Pan().activeOffsetX([-12,12]).failOffsetY([-16,16])` — так горизонтальный
    свайп забирает жест, а вертикальный проваливается в скролл экрана.
  - `onStart`: `cancelAnimation(pos)` + запомнить стартовую позицию.
  - `onUpdate`: rubber-band за краями (делить избыток на 3).
  - `onEnd`: `Math.round` до ближайшего индекса + оверрайд по `velocityX`
    (флик быстрее ~250px/s продвигает на слайд дальше, даже если сам drag
    не дотянул до половины) → `withTiming(idx * SLIDE_WIDTH, {duration:420,
    easing: Easing.out(Easing.cubic)})`.
  - Однонаправленный рост точки при активности (без раздувания в обе стороны):
    рендерить ряд точек с `flexDirection: 'row-reverse'` + маппить по
    `[...indices].reverse()`.
  - `GestureDetector` можно юзать где угодно без доп. настройки — `GestureHandlerRootView`
    уже оборачивает всё приложение в `app/_layout.tsx`.
  - Образец: `app/(tabs)/index.tsx` — слайдер целей (`goalPos`, `GoalDot`, `goalPan`).

## Workflow с пользователем

- Один экран за раз. Если задача про конвертер — НЕ грепать по всему проекту,
  НЕ читать DataContext/selectors/AssetRow «на всякий случай». Открыть нужный
  файл, поправить, проверить tsc. Сквозные правки делаем только когда явно сказано.
- **Сборки копим в пачку.** Не пересобирать APK после каждой мелочи (отступ, цвет).
  Накопил 3–5 правок → один build + один релиз. Версию бампать только при сборке.
- **Версия отражает только само приложение.** Правки тулинга/доков (`dev-restart.bat`,
  `DEV_RESTART.md`, `CLAUDE.md` и т.п.) коммитятся ОТДЕЛЬНО от кода экранов/логики,
  без бампа версии — даже если делались в той же сессии подряд. Бамп версии — только
  когда в коммите реально есть изменения `app/`, `src/` (то, что попадёт в APK).
- **Ассеты пользователь меняет сам** (кладёт новые PNG в `assets/` поверх старых) —
  это НЕ повод для коммита. Увидел изменённый ассет в git status → не трогать,
  закоммитится пачкой с очередными правками кода.
- Прямо в `main`, без feature-веток и PR. Тег `vX.Y.Z`, релиз через `gh`.
- GH_TOKEN — пользователь даёт per-session, не хранить.
- TypeScript-чек обязателен перед сборкой: `npx tsc --noEmit`.
